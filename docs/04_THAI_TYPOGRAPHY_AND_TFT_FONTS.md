# 04. ระบบการแสดงผลฟอนต์ไทยและ Pre-rendered TFT (Thai Typography & TFT Fonts)

เอกสารนี้ระบุวิธีแก้ปัญหาทางเทคนิคที่ยากและซับซ้อนที่สุดในวิชวลโนเวลญี่ปุ่น: **การแสดงผลสระ-วรรณยุกต์ไทย และการกำจัดปัญหากล่องสี่เหลี่ยมเต้าหู้ `[]` รวมถึงวรรณยุกต์ลอย/เว้นวรรคห่าง**

---

## 1. ทำไมภาษาไทยถึงพังในเอนจินเกมญี่ปุ่น? (The Root Cause)

เอนจิน Kirikiri Z พัฒนาขึ้นมาสำหรับภาษาญี่ปุ่น (CJK):
1. **ไม่มีเอนจิน Complex Text Layout (CTL):** ไม่มี HarfBuzz ในการคำนวณตำแหน่งสระซ้อนและวรรณยุกต์
2. **ระบบการเลื่อนเคอร์เซอร์ (Advance):** เอนจินมองว่าทุกตัวอักษรมีความกว้างแบบโมโนสเปซหรือพิกเซลเต็มตัว เมื่อเจอสระบน (เช่น ิ) หรือวรรณยุกต์ (เช่น ่) แทนที่จะพิมพ์ทับบนพยัญชนะ เอนจินกลับเลื่อนเคอร์เซอร์ไปข้างหน้า ส่งผลให้**วรรณยุกต์ลอยเดี่ยวและเว้นวรรคกว้าง**
3. **ระบบแคชฟอนต์ TVP Pre-rendered Font (`.tft`):** เกมของ Yuzusoft ไม่ได้วาดตัวอักษรจาก TrueType `.ttf` สดๆ แต่จะดึงภาพบิตแมปที่พรีเรนเดอร์ไว้ล่วงหน้าจากไฟล์ `.tft` ใน `data.xp3` ซึ่งมีเฉพาะตัวอักษรภาษาญี่ปุ่น 2,923 ตัว เมื่อมีรหัสภาษาไทย ($U+0E01 \dots U+0E5B$) หรือรหัส PUA จึงแสดงผลเป็น**กล่องสี่เหลี่ยมเต้าหู้ `[]`**

---

## 2. โครงสร้างไบนารีของไฟล์ฟอนต์ `.tft` (TVP Pre-rendered Font Spec)

ไฟล์ `.tft` มีโครงสร้างไบนารีมาตรฐานดังนี้:

### ก. Header (36 ไบต์)
* `0..21` (22B): Magic String `b"TVP pre-rendered font\x1a"`
* `22` (1B): Version
* `23` (1B): Unicode Flag (1 = UTF-16)
* `24..27` (4B): Total Glyph Count (จำนวนอักขระในไฟล์)
* `28..31` (4B): `ch_index_off` (พิกัดเริ่มต้นตารางรหัสตัวอักษร)
* `32..35` (4B): `metric_index_off` (พิกัดเริ่มต้นตารางเมทริกซ์)

### ข. ตารางรหัสอักขระ (Character Index Table)
* อาร์เรย์ของ `uint16` (2 ไบต์ต่อ 1 ตัวอักษร) เรียงลำดับจากรหัสน้อยไปมาก

### ค. ตารางขนาดและตำแหน่งอักขระ (Glyph Metric Records - 20 ไบต์ต่ออักขระ)
```c
struct TFT_MetricRecord {
    uint32_t glyph_offset; // ตำแหน่งบิตแมป RLE ในไฟล์ (0 หากเป็นช่องว่าง)
    uint16_t width;        // ความกว้างของบิตแมป (w)
    uint16_t height;       // ความสูงของบิตแมป (h)
    int16_t  origin_x;     // ตำแหน่งแกน X เทียบกับจุด基準 (ox)
    int16_t  origin_y;     // ตำแหน่งแกน Y เทียบกับเส้นบรรทัดฐาน (oy)
    int16_t  inc_x;        // ระยะเลื่อนเคอร์เซอร์แนวนอนไปตัวถัดไป (สำคัญมาก!)
    int16_t  inc_y;        // ระยะเลื่อนเคอร์เซอร์แนวตั้ง (ปกติเป็น 0)
    int16_t  inc;          // ระยะเลื่อนพื้นฐาน (เท่ากับ inc_x)
    uint16_t reserved;     // ปกติเป็น 0
};
```

### ง. การบีบอัดภาพบิตแมป (RLE Compression)
ภาพตัวอักษรแต่ละตัวถูกบีบอัดด้วย RLE (Run-Length Encoding) โดยค่าพิกเซลระดับสีเทา 0..64:
* ไบต์ค่า `0x00 .. 0x40`: พิกเซลเดี่ยวที่มีค่าสีเทา $0 \dots 64$
* ไบต์ค่า `>= 0x41`: สั่งให้ทำซ้ำพิกเซลก่อนหน้าจำนวน `byte - 0x40` ครั้ง

## 3. ทางออกวิศวกรรม: Zero-Advance Metrics & PUA Shaper

เพื่อให้เอนจิน Kirikiri วาดภาษาไทยได้อย่างถูกต้องสมบูรณ์ เราใช้กลยุทธ์ 2 ชั้น:

### ชั้นที่ 1: การกำหนด Zero-Advance (`incX = 0`)
สำหรับสระและวรรณยุกต์ภาษาไทยมาตรฐานทั้งหมด เรากำหนดให้ระยะการเลื่อนเคอร์เซอร์เป็นศูนย์:
```python
THAI_COMBINING_MARKS = {
    0x0E31,  # ั (ไม้หันอากาศ)
    0x0E34,
    0x0E35,
    0x0E36,
    0x0E37,  # ิ ี ึ ื
    0x0E38,
    0x0E39,
    0x0E3A,  # ุ ู ฺ
    0x0E47,  # ็ (ไม้ไต่คู้)
    0x0E48,
    0x0E49,
    0x0E4A,
    0x0E4B,
    0x0E4C,  # ่ ้ ๊ ๋ ์
    0x0E4D,  # ํ (นฤคหิต)
    0x0E4E,  # ๎ (ยามักการ)
}

# เมื่อสร้าง Glyphs:
if cp in THAI_COMBINING_MARKS:
  glyph["incX"] = 0
  glyph["incY"] = 0
  glyph["inc"] = 0
```
**ผลลัพธ์:** เมื่อพิมพ์สระหรือวรรณยุกต์ เคอร์เซอร์จะไม่ขยับไปข้างหน้า ทำให้สระ/วรรณยุกต์นั้นซ้อนอยู่บนพยัญชนะตัวเดิมได้อย่างถูกต้องทันที!

---

### ชั้นที่ 2: ระบบรหัส PUA (Private Use Area $U+F700 \dots U+F71F$)
การทำ `incX = 0` แก้ปัญหาการเว้นวรรคได้ แต่ยังเจอปัญหา:
1. **วรรณยุกต์ชนสระบน:** เช่น คำว่า `ที่` หรือ `ขึ้น` ถ้าใช้วรรณยุกต์ตำแหน่งปกติ ไม้เอก/ไม้โทจะทับสระอิ/สระอือ
2. **พยัญชนะหางยาว:** เช่น `ป`, `ฝ`, `ฟ` สระบนและวรรณยุกต์จะชนหางพยัญชนะ

เราจึงสร้าง Glyph พิเศษในย่าน PUA 32 ตัว:

| ช่วงรหัส PUA | ความหมายและการจัดตำแหน่งพิเศษ |
| :---: | :--- |
| **`0xF700`** | **ฐ** แบบตัดเชิงล่างออก เพื่อไม่ให้ชนสระอุ/สระอู |
| **`0xF701 .. 0xF704`** | **สระบน (ิ, ี, ึ, ื)** เยื้องซ้าย (Shift-Left $-5\text{ px}$) สำหรับ ป, ฝ, ฟ |
| **`0xF705 .. 0xF709`** | **วรรณยุกต์ (่, ้, ๊, ๋, ์)** เยื้องซ้าย (Shift-Left $-5\text{ px}$) สำหรับ ป, ฝ, ฟ |
| **`0xF70A .. 0xF70E`** | **วรรณยุกต์ระดับปกติ (่, ้, ๊, ๋, ์)** วางบนพยัญชนะทั่วไป |
| **`0xF70F`** | **ญ** แบบตัดเชิงล่างออก เพื่อไม่ให้ชนสระอุ/สระอู |
| **`0xF710 .. 0xF712`** | **ไม้หันอากาศ (ั), นฤคหิต (ํ), ไม้ไต่คู้ (็)** เยื้องซ้าย สำหรับ ป, ฝ, ฟ |
| **`0xF713 .. 0xF717`** | **วรรณยุกต์ระดับสูง (High Level)** ยกความสูงขึ้น $+8\text{ px}$ ถึง $+10\text{ px}$ เพื่อลอยเหนือสระบนอย่างสง่างาม ไม่ทับซ้อนกัน |
| **`0xF718 .. 0xF71A`** | **สระล่าง (ุ, ู, ฺ)** เยื้องต่ำลง สำหรับพยัญชนะหางยาวล่าง |
| **`0xF71B .. 0xF71F`** | **วรรณยุกต์บนสระอำ** ยกความสูงเพื่อหลบวงกลมของสระอำ |

## 4. สองไฟล์ฟอนต์ที่ต้องแทนที่ใน `data.xp3`

เกม Senren * Banka และเกม Yuzusoft ใช้ฟอนต์ 2 ขนาด:

1. **`font1_32.tft` (Member 8):**
   - ใช้ในกล่องบทสนทนาหลัก
   - เรนเดอร์ด้วยความสูงฟอนต์ `font_height = -36px`
   - การเข้ารหัสใน `data.xp3`: Dual-Key XOR ด้วย `0x54` (ไบต์ 0..2154) และ `0x56` (ไบต์ 2154..End)
2. **`font1_39.tft` (Member 9):**
   - ใช้ในหน้าต่าง Backlog / ประวัติบทพูดย้อนหลัง (History)
   - เรนเดอร์ด้วยความสูงฟอนต์ `font_height = -44px`
   - การเข้ารหัสใน `data.xp3`: Dual-Key XOR ด้วย `0x43` (ไบต์ 0..2134) และ `0x4c` (ไบต์ 2134..End)

> [!IMPORTANT]
> หากแก้เฉพาะ `font1_32` แต่ไม่แก้ `font1_39` บทสนทนาในหน้าจอหลักจะสวยงาม แต่ทันทีที่ผู้เล่นเปิดหน้า Log ดูย้อนหลัง จะเจอกล่องเต้าหู้ `[]` และสระลอยเต็มหน้าจอทันที การแทนที่ทั้งสองไฟล์จึงเป็นข้อกำหนดบังคับ

## 5. ข้อกำหนดของโหมดฟอนต์ (`faceMode = 0`) และโปรแกรมติดตั้งตอนจบโปรเจกต์

นอกจากการฝังฟอนต์ `.tft` ลงในเกมแล้ว สิ่งที่สำคัญที่สุดคือ**การควบคุมให้เอนจินเกมเรียกใช้ฟอนต์ในโหมดที่ถูกต้อง**:

### ก. กับดัก `faceMode = 1` (Windows GDI Fallback)
* ใน `%APPDATA%\Yuzusoft\SenrenBanka\datasc.ksd` เอนจินบันทึกค่า `faceMode`:
  * `faceMode = 0`: ใช้ฟอนต์ TFT บิตแมปของเกม (แสดงผลภาษาไทยถูกต้อง 100%)
  * `faceMode = 1`: บายพาสฟอนต์ในเกม แล้วเรียกฟอนต์ระบบของ Windows ซึ่งจะดีดกลับไปเป็น `MS Gothic` ทำให้เกิดกล่องสี่เหลี่ยมเต้าหู้ `[]` (ขาดรหัส PUA) และสระเว้นวรรคห่างเป็นช่องๆ

### ข. ข้อกำหนดของโปรแกรมติดตั้งม็อดแปลไทย (Installer Specs)
เมื่อทำโปรแกรมติดตั้งแพตช์ภาษาไทย (Installer `.exe` หรือ `.bat`) ตอนจบโปรเจกต์ โปรแกรมติดตั้งจะต้องมีขั้นตอนบังคับ:
1. **แก้ไฟล์ `datasc.ksd` อัตโนมัติ:** ค้นหาโฟลเดอร์ `%APPDATA%\Yuzusoft\SenrenBanka\` และบังคับเปลี่ยน `"faceMode" => 1,` ให้เป็น `"faceMode" => 0,`
2. **ติดตั้งฟอนต์คู่ขนาน (Dual-Redundancy):** คัดลอก `font1_32.tft` และ `font1_39.tft` ไปไว้ในโฟลเดอร์ `font/` ของเกมโดยตรงด้วย นอกเหนือจากการฉีดเข้า `data.xp3`
