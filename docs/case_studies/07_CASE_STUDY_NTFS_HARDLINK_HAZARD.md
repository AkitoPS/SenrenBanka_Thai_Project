# กรณีศึกษาที่ 07: อันตรายของ NTFS Hard-link และการเขียนทับไฟล์อย่างปลอดภัย
## (Case Study: The NTFS Hard-link Hazard & Safe Atomic File Replacement)

---

## 1. เหตุการณ์และข้อผิดพลาด (The Incident)

ในระหว่างการทดสอบในขั้นตอนต้นๆ เพื่อประหยัดพื้นที่ฮาร์ดดิสก์เนื่องจากไฟล์เกมแต่ละชุดมีขนาดใหญ่กว่า 10 GB:
- สคริปต์ทดสอบหลายตัวใช้คำสั่งสร้าง **NTFS Hard-link (`os.link`)** เพื่อจำลองไฟล์ `.xp3` เช่น `data.xp3` และ `video.xp3` ข้ามไปยังโฟลเดอร์ทดสอบต่างๆ (`step28`, `step36`, `working`) โดยไม่ต้องคัดลอกไฟล์จริงซ้ำซ้อน

**ผลข้างเคียงร้ายแรงที่เกิดขึ้นโดยไม่รู้ตัว (Collateral Damage):**
- เมื่อเราเขียนโค้ดเปิดไฟล์ `data.xp3` แบบ `open(..., 'r+b')` เพื่อฉีดแก้ไขข้อมูลในโฟลเดอร์ทดสอบแห่งหนึ่ง **ไฟล์ `data.xp3` ในโฟลเดอร์อื่นๆ ที่เชื่อมโยงด้วย Hard-link เดียวกัน ถูกแก้ไขตามไปด้วยทั้งหมดโดยอัตโนมัติ!**
- ส่งผลให้สภาพแวดล้อมที่ตั้งใจจะแยกอิสระ (Isolated Environments) ถูกทำลาย และทำให้ไฟล์ต้นฉบับสูญเสียความบริสุทธิ์

---

## 2. การสืบสวนสาเหตุ (Root Cause Analysis)

1. **กลไกของ NTFS Hard-link:**
   - Hard-link ใน Windows/NTFS ไม่ใช่การสร้างไฟล์ใหม่ แต่เป็นการสร้าง **Pointer ตัวที่ 2 ชี้ไปยัง Physical Inode/Cluster เดียวกันบนฮาร์ดดิสก์**
   - เมื่อเปิดไฟล์เขียนทับ Inode นั้น ทุกโฟลเดอร์ที่มี Pointer ชี้อยู่จะเห็นการเปลี่ยนแปลงพร้อมกันทันที
2. **การตรวจจับ Hard-link Count:**
   - ใน Python เราสามารถตรวจสอบได้ผ่าน `os.stat(filepath).st_nlink`:
     - หาก `st_nlink > 1` แสดงว่าไฟล์นั้นมีการเชื่อมโยงกับโฟลเดอร์อื่นอยู่

---

## 3. ทางออกทางวิศวกรรม: การตัดการเชื่อมโยงอย่างเด็ดขาด (Unlink & Atomic Replace)

ในสคริปต์ฉีดข้อมูลเวอร์ชันสมบูรณ์ เรากำหนดมาตรฐานการแทนที่ไฟล์ใหม่ที่ปลอดภัย 100%:

```python
# 1. เขียนข้อมูลใหม่ลงในไฟล์ชั่วคราว (.new หรือ .tmp)
temp_output = target_xp3 + '.new'
with open(temp_output, 'wb') as f:
  f.write(new_archive_bytes)

# 2. ตรวจสอบขนาดว่าเขียนลงดิสก์ครบถ้วน
assert os.path.getsize(temp_output) == len(new_archive_bytes)

# 3. ลบตัวเชื่อมโยงเดิมทิ้ง (Break Hard-link cleanly)
if os.path.exists(target_xp3):
  os.remove(target_xp3)  # คำสั่ง remove จะลด st_nlink ลง 1 โดยไม่ทำลายไฟล์ปลายทางอื่น

# 4. เปลี่ยนชื่อไฟล์ใหม่มาแทนที่ (Atomic Rename)
os.rename(temp_output, target_xp3)
```

* **ผลลัพธ์:** ไฟล์ที่ได้จะมี `st_nlink = 1` เสมอ กลายเป็นไฟล์เดี่ยวอิสระที่ปลอดภัย และการแก้ไขจะไม่มีทางส่งผลกระทบข้ามสายงานอีกต่อไป

---

## 4. บทเรียนทางวิศวกรรมที่นำไปใช้ในอนาคต (Lessons Learned)

1. **ห้ามใช้ Hard-link กับไฟล์ที่จะมีการแก้ไข (Read-Only Only):**
   - อนุญาตให้ใช้ Hard-link ได้เฉพาะกับ Asset ขนาดใหญ่ที่**ไม่มีการแก้ไขเด็ดขาด** (เช่น `video.xp3`, `voice.xp3`)
2. **ไฟล์ที่มีการแพตช์ (data.xp3, patch_extra.xp3) ต้องเป็นไฟล์เดี่ยวเสมอ:**
   - ต้องตัด Hard-link ก่อนทำการฉีดข้อมูลทุกครั้ง เพื่อความปลอดภัยของโฟลเดอร์ต้นฉบับ
