# กรณีศึกษาที่ 01: วิกฤตเซฟเกมหาย และการจัดการ State ของเอนจิน
## (Case Study: Save Game Loss Crisis & Engine State Isolation)

---

## 1. เหตุการณ์วิกฤต (The Incident)

ในขั้นตอนการทดสอบรันเกม ผู้ใช้ส่งข้อความแจ้งเตือนด้วยความตกใจอย่างยิ่ง:
> *"ชิบหายแล้ว ข้อมูลเกมที่เซฟไว้หายหมดเลยทั้งในโฟลเดอร์นี้และเปิดผ่านสตีม ทำไม และเปิดเกมไม่เป็นภาษาไทยแล้ว เกิดอะไรขึ้น"*

ผู้ใช้พบว่าไฟล์บันทึกการเล่นเกม (Save data) จำนวนกว่า **75 เซฟ** ที่เล่นสะสมมาอย่างยาวนาน ไม่ปรากฏในหน้า Load Game เมื่อเปิดเกม ทั้งในโฟลเดอร์ทดสอบและเมื่อเปิดผ่านคลัง Steam โดยตรง

---

## 2. การสืบสวนหาสาเหตุเชิงลึก (Root Cause Investigation)

จากการตรวจสอบการทำงานของเอนจิน Kirikiri Z และระบบ Steam Cloud พบสาเหตุ 3 ประการที่ซ้อนทับกัน:

1. **กลไกการค้นหาโฟลเดอร์เซฟของ Kirikiri Z (`savedata` Path Resolution):**
   - เอนจิน Kirikiri Z กำหนดตำแหน่งบันทึกข้อมูลเซฟสัมพันธ์กับ **Current Working Directory (CWD)** ของโพรเซสที่เปิดรัน
   - เมื่อเรารันเกมผ่านโฟลเดอร์ทดสอบย่อย (เช่น `builds/step28_canary_test/` หรือ `step36/`) ตัวเกมจะมองหาโฟลเดอร์ `savedata/` ที่อยู่ในโฟลเดอร์ย่อยนั้นๆ แทนที่จะเป็นโฟลเดอร์หลัก
2. **ไฟล์ตรวจสอบความถูกต้องของเซฟ (`savecheck` และ `steam_autocloud.vdf`):**
   - ในโฟลเดอร์ `savedata/` จะมีไฟล์ไบนารีขนาด 44 ไบต์ชื่อ `savecheck`
   - หากไฟล์ `savecheck` ไม่ตรงกับดัชนี หรือมีไฟล์ภาพแคปเจอร์ `.bmp` แต่ไม่มีการลงทะเบียนในระบบ เอนจินจะมองว่าเซฟไม่ถูกต้องและซ่อนเซฟทั้งหมดไว้ไม่ให้แสดงในหน้าเมนู
3. **พฤติกรรมของ Steam Cloud Sync:**
   - เมื่อเปิดเกมผ่าน Steam ขณะที่ไฟล์ `.xp3` ในเครื่องมีสถานะไม่ตรงกับ Cloud ตัวไคลเอนต์ Steam จะเกิดความสับสนในการ Sync ทำให้ไฟล์ในโฟลเดอร์เครื่องชะงักชั่วคราว

---

## 3. การกู้คืนข้อมูล (Recovery Action)

โชคดีเป็นอย่างยิ่งที่เราได้ทำสำรองข้อมูล (Backup) ไฟล์เซฟทั้งหมดของผู้ใช้เก็บไว้ล่วงหน้าอย่างปลอดภัยในโฟลเดอร์ **`backup_user_saves/`** (ประกอบด้วยไฟล์บันทึก 78 ไฟล์ ขนาดรวม 30.79 MB):

1. คัดลอกไฟล์ทั้งหมดจาก `backup_user_saves/` กลับคืนสู่:
   - `C:\Program Files (x86)\Steam\steamapps\common\SenrenBanka\savedata\`
   - `SenrenBanka_THAI_PLAYABLE\savedata\`
2. ตรวจสอบไฟล์ `savecheck` และภาพ Thumbnails (`data_*.bmp`) พบว่าครบถ้วน 100%
3. เมื่อเปิดเกม ข้อมูลเซฟทั้ง 75 สล็อตกลับมาสมบูรณ์ครบถ้วนทุกฉากทุกรูท

---

## 4. บทเรียนทางวิศวกรรมที่นำไปใช้ในอนาคต (Lessons Learned & Golden Rules)

1. **กฎเหล็กข้อที่ 1: ห้ามแตะต้องโฟลเดอร์ Steam จริงจนกว่าจะทดสอบผ่าน 100%:**
   - การทำงานต้องทำบนโฟลเดอร์จำลองเดี่ยว (`SenrenBanka_THAI_PLAYABLE`) เท่านั้น
2. **กฎเหล็กข้อที่ 2: การสำรองข้อมูลต้องอยู่นอกพื้นที่ทำงาน (External Backup):**
   - โฟลเดอร์ `backup_user_saves/` ต้องคงอยู่ถาวร และไม่อยู่ในพาธที่จะถูกสคริปต์อัตโนมัติเขียนทับ
3. **กฎเหล็กข้อที่ 3: บังคับ Working Directory ในตัว Launcher เสมอ:**
   - ในไฟล์ `Start_Thai_Game.bat` ต้องใส่คำสั่ง:
     ```bat
     cd /d "%~dp0"
     ```
     คำสั่งนี้จะบังคับให้เอนจินเกมมองเห็นโฟลเดอร์ที่ตัวมันเองอยู่เป็น Root เสมอ ไม่ว่าผู้ใช้จะเปิดเกมผ่านชอร์ตคัตหรือคลิกจากที่ใดก็ตาม ป้องกันปัญหาเซฟชี้ผิดโฟลเดอร์อย่างถาวร
