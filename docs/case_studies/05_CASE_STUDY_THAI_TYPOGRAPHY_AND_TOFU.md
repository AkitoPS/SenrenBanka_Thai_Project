# กรณีศึกษาที่ 05: ปริศนาตัวหนังสือเต้าหู้ `[]` และสระ-วรรณยุกต์ลอย
## (Case Study: Tofu Glyphs `[]`, Floating Diacritics & PUA Resolution)

---

## 1. ปัญหาทางสายตา (Visual Defects Reported)

เมื่อเริ่มแสดงผลภาษาไทยในเกมเป็นครั้งแรก ผู้ใช้ส่งภาพแคปเจอร์หน้าจอรายงานปัญหาทัศนวิสัยร้ายแรง:
1. **ตัวหนังสือเต้าหู้ `[]`:** ข้อความเต็มไปด้วยกล่องสี่เหลี่ยมว่างเปล่า โดยเฉพาะตำแหน่งที่มีสระและวรรณยุกต์
2. **ตัวหนังสือลอยและเว้นวรรคห่าง:** คำภาษาไทย เช่น `ที่นี่` แสดงผลกลายเป็น `ท  ี่  น  ี่` ตัววรรณยุกต์และสระลอยเคว้งคว้างอยู่คนละตำแหน่งกับพยัญชนะ

---

## 2. การสืบสวนสาเหตุทางวิศวกรรมการพิมพ์ (Typographical Root Cause)

### ก. ทำไมถึงเกิดกล่องสี่เหลี่ยมเต้าหู้ `[]`?
- เอนจิน Kirikiri Z อาศัยไฟล์ฟอนต์พรีเรนเดอร์บิตแมป `.tft` (`TVP pre-rendered font`)
- ในไฟล์ต้นฉบับ `font1_32.tft` มีการเรนเดอร์อักขระไว้เพียง **2,923 ตัว** ซึ่งประกอบด้วย ASCII ภาษาอังกฤษ, คันจิ, ฮิรางานะ และคาตาคานะ
- ในไฟล์ไม่มีภาพ Glyph ของภาษาไทย ($U+0E01 \dots U+0E5B$) และไม่มีอักขระ PUA เลย
- เมื่อเอนจินได้รับรหัสอักขระที่ไม่มีในตาราง เอนจินจะวาดสัญลักษณ์ Fallback สี่เหลี่ยมว่างเปล่า (Tofu) แทน

### ข. ทำไมสระและวรรณยุกต์ถึงลอยและเว้นวรรคกว้าง?
- ในระบบอักขระภาษาญี่ปุ่น อักษรทุกตัว (รวมถึงคานะตัวเล็ก) จะมีค่า **`incX` (Horizontal Cell Advance)** เป็นบวกเสมอ เพื่อขยับเคอร์เซอร์ไปทางขวาสำหรับตัวอักษรตัวถัดไป
- ในภาษาไทย สระบน (ิ, ี, ึ, ื) และวรรณยุกต์ (่, ้, ๊, ๋, ์) เป็น **Combining Marks** ซึ่งตามหลักสากลต้องพิมพ์ทับบนพยัญชนะเดิมโดย**ไม่ขยับเคอร์เซอร์**
- แต่เอนจิน Kirikiri Z ไม่มีตัวประมวลผล OpenType Layout (ไม่มี HarfBuzz) เอนจินจึงนำค่า Advance ของฟอนต์มาเลื่อนเคอร์เซอร์ไปข้างหน้า ส่งผลให้สระและวรรณยุกต์ถูกผลักไปอยู่ข้างพยัญชนะเหมือนเป็นตัวอักษรเดี่ยว

## 3. สองนวัตกรรมทางวิศวกรรมที่แก้ไขได้ 100% (The Dual Breakthrough)

เราได้คิดค้นและนำกลยุทธ์ 2 ชั้นมาใช้งานผ่านโปรแกรม [`method/tools/build_extended_tft.py`](file:///c:/Users/DELL/Desktop/VN_Thai_Project/method/tools/build_extended_tft.py):

### นวัตกรรมที่ 1: กำหนด Zero-Advance Metrics (`incX = 0`)
ในตาราง Glyph Metrics ของไฟล์ `.tft` เราบังคับให้สระและวรรณยุกต์ไทยทั้งหมดมีระยะเลื่อนเคอร์เซอร์เป็นศูนย์:
```python
THAI_COMBINING_MARKS = {0x0E31, 0x0E34, ..., 0x0E4C}

if codepoint in THAI_COMBINING_MARKS:
  metric['incX'] = 0
  metric['incY'] = 0
  metric['inc'] = 0
```
* **ผลลัพธ์:** เมื่อเอนจินวาดสระหรือวรรณยุกต์ เคอร์เซอร์จะหยุดนิ่งอยู่ที่ตำแหน่งเดิม สระจึงตกลงบนหัวพยัญชนะได้อย่างแม่นยำ ไม่เว้นวรรคห่างอีกต่อไป!

---

### นวัตกรรมที่ 2: ระบบรหัส PUA (Private Use Area $U+F700 \dots U+F71F$)
แม้จะแก้เรื่องระยะเลื่อนได้แล้ว แต่ยังพบปัญหา**วรรณยุกต์ชนสระบน** (เช่น คำว่า `ที่` ไม้เอกจะทับสระอี) และ**ชนหางพยัญชนะสูง** (ป, ฝ, ฟ)

เราจึงสร้าง Glyph พิเศษ 32 ตัวในย่าน PUA:
1. **วรรณยุกต์ระดับสูง (High Tones: $U+F713 \dots U+F717$):**
   - ยกพิกัดแกน Y สูงขึ้น $+8\text{ px}$ ถึง $+10\text{ px}$ เมื่อมีสระบนรองรับ
2. **สระ/วรรณยุกต์เยื้องซ้าย (Shift-Left: $U+F701 \dots U+F709$):**
   - เลื่อนพิกัดแกน X ไปทางซ้าย $-5\text{ px}$ เพื่อหลบหางของ ป, ฝ, ฟ
3. **พยัญชนะตัดเชิง (Truncated: $U+F700, U+F70F$):**
   - ตัดหางล่างของ ฐ และ ญ ออกเพื่อไม่ให้ชนสระอุ/สระอู

## 4. บทเรียนทางวิศวกรรมที่นำไปใช้ในอนาคต (Lessons Learned)

1. **อย่าพึ่งพาเอนจินในการจัดสระ ให้ควบคุมระดับ Metrics ไบนารี:**
   - การแก้ปัญหาภาษาไทยในวิชวลโนเวลญี่ปุ่น ต้องแก้ที่ระดับไฟล์ฟอนต์ `.tft` โดยตรง การปรับ `incX = 0` คือหัวใจสำคัญที่สุด
2. **ทำ Pre-processing ข้อความด้วย PUA Shaper เสมอ:**
   - ข้อความภาษาไทยก่อนจะถูกฉีดเข้าสู่เกม ต้องผ่านโมดูล [`thai_pua_shaper.py`](file:///c:/Users/DELL/Desktop/VN_Thai_Project/method/tools/thai_pua_shaper.py) เพื่อแปลงสระซ้อนเป็นรหัส PUA ที่เตรียมไว้ในฟอนต์เสมอ
