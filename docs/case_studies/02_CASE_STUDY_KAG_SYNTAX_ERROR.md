# กรณีศึกษาที่ 02: บั๊กมรณะ `start.ks:43 Syntax error` และบทพูดเปิดเกมหลุด
## (Case Study: The Fatal `start.ks:43` Syntax Error & Missing Dialogue)

---

## 1. เหตุการณ์วิกฤต (The Incident)

หลังจากการแพตช์บทแปลชุดแรก (Batch 1.1) ผู้ใช้เปิดเล่นและรายงานข้อผิดพลาดร้ายแรง 2 จุด:
> *"สามประโยคแรกไม่ได้รับการแปล และเมื่อเล่นไปเรื่อยๆ ขึ้นข้อความนี้
> 致命的なエラーが発生しました。
> ファイル:start.ks 行:43
> タグ:不明(←エラーの発生した前後のタグを示している場合もあります)
> Syntax error (syntax error)"*

ตัวเกมแครชกลางคันขณะเล่นบทนำ และขึ้นกล่องแจ้งเตือน Fatal Error พร้อมทั้งมี 3 ประโยคแรกของคนขับแท็กซี่ยังคงเป็นภาษาอังกฤษหลุดมา

---

## 2. การสืบสวนหาสาเหตุเชิงลึก (Root Cause Investigation)

### ก. ปัญหาบั๊ก `start.ks:43 Syntax error (タグ:不明)`
เมื่อเราแกะสคริปต์ `start.ks` ออกมาตรวจสอบ:
1. บรรทัดที่ 43 ของ `start.ks` เป็นคำสั่งเรียกใช้ KAG Scenario Parser ในการประมวลผลแท็กของบล็อกข้อความ
2. **การทำงานของ KAG Lexer/Parser ใน Kirikiri Z:**
   - ใน KAG ไวยากรณ์ของแท็กคำสั่งจะสิ้นสุดลงด้วยการขึ้นบรรทัดใหม่ (`\n` หรือ `\r\n`)
   - ในไฟล์ `.ks.scn` ข้อความบทสนทนาจะถูกส่งเข้าไปในแท็กแสดงข้อความ เช่น `[text val="..."]`
3. **สาเหตุของข้อผิดพลาด:**
   - ในกระบวนการแปลภาษาไทยของผู้แปลหรือสคริปต์ตัดคำ มีตัวอักษร **ขึ้นบรรทัดใหม่แบบดิบ (`\n`)** หลุดเข้าไปอยู่ภายในสตริงข้อความบทพูด
   - เมื่อ KAG Lexer กำลังอ่านแท็ก `[text val="..."]` แล้วมาเจอ `\n` กลางคัน ตัว Lexer จะเข้าใจว่าคำสั่งแท็กนั้นจบลงแล้ว ทั้งที่ยังไม่มีเครื่องหมายปิดวงเล็บ `]`
   - ผลลัพธ์: KAG ไม่สามารถระบุแท็กได้ (`タグ:不明`) และโยนข้อผิดพลาด **Syntax error (syntax error)** ออกมา ทำให้เกมแครชทันที!

### ข. ปัญหา 3 ประโยคแรกไม่ได้รับการแปล
- 3 ประโยคแรกของเกมคือ:
  1. `Taxi Driver`: *"Sir."*
  2. `Masaomi`: *"...Hm?"*
  3. `Taxi Driver`: *"Sir?"*
- **สาเหตุ:**
  - สคริปต์สกัดข้อความเดิมเริ่มนับ Index จากข้อความที่ 4 (เนื่องจากข้ามข้อความสั้นที่มีคำซ้ำ)
  - ฐานข้อมูลบทแปลจึงไม่มีคู่คำแปลของ 3 ประโยคแรก ตัวเอนจินจึงแสดงผลเป็นภาษาอังกฤษต้นฉบับ

---

## 3. ทางออกและการแก้ไข (The Resolution)

1. **เพิ่มคู่แปล 3 ประโยคแรกในฐานข้อมูลบทแปล:**
   - `Sir.` $\rightarrow$ `คุณลูกค้าครับ`
   - `...Hm?` $\rightarrow$ `...หือ?`
   - `Sir?` $\rightarrow$ `คุณลูกค้าครับ?`
2. **สร้างระบบฆ่าเชื้อสตริง (String Sanitization Layer):**
   ในสคริปต์ฉีดบทพูด (`inject_psb_strings.py`) เราสร้างตัวกรองเพื่อกำจัด literal `\n` และ `\r` ทั้งหมด:
   ```python
   # ลบตัวอักษรขึ้นบรรทัดใหม่ทั้งหมดออกจากข้อความสตริง
   th_clean = (
       th_raw.replace('\r\n', ' ').replace('\n', ' ').replace('\r', ' ')
   )

   # แปลง Single Quote ป้องกันปัญหา TJS parser
   th_clean = th_clean.replace("'", '’')
```
3. เมื่อคอมไพล์และแพตช์ใหม่ ตัวเกมเล่นผ่านจุดเดิมได้อย่างราบรื่น ไม่มีการแจ้งเตือน Syntax Error อีกต่อไป

---

## 4. บทเรียนทางวิศวกรรมที่นำไปใช้ในอนาคต (Lessons Learned)

1. **ห้ามปล่อยให้มี `\n` หรือ `\r` ใน String Pool ของ PSB เด็ดขาด:**
   - ข้อความบทพูดของ Visual Novel ในเอนจิน Kirikiri Z ต้องเป็น Single-line String เสมอ
   - การตัดบรรทัดบนหน้าจอต้องใช้การแบ่งวรรค หรือปล่อยให้เอนจินตัดคำตามความกว้างกล่องข้อความ
2. **ต้องระวังเครื่องหมายคำพูด Single Quote (`'`):**
   - ใน TJS2 เครื่องหมาย `'` เป็นตัวเปิดสตริง หากมีหลุดไป อาจทำให้ตัวประมวลผลสับสน ควรแทนที่ด้วย Typographic Quote (`’`) หรือคำภาษาไทย
3. **ตรวจสอบความสมบูรณ์ตั้งแต่บรรทัดที่ 0 (Index 0 Verification):**
   - ก่อนจะเริ่มส่งมอบแพตช์ ต้องมีสคริปต์ตรวจนับว่าประโยคแรกสุดในไฟล์ `.ks.scn` ได้รับการแปลครบถ้วนแล้วเสมอ
