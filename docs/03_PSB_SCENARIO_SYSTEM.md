# 03. โครงสร้างสคริปต์ PSB และการสกัด/ฉีดบทสนทนา (PSB Scenario System)

เอกสารนี้ระบุรายละเอียดโครงสร้างไฟล์สคริปต์สเกนาริโอ **PSB (Pure Serialization Binary)** ที่ใช้ในเกม Yuzusoft, การถอด/เข้ารหัส Dual-Key XOR, โครงสร้าง String Pool และข้อควรระวังเรื่อง Syntax Error

---

## 1. รูปแบบไฟล์สเกนาริโอ (`.ks.scn`)

ในเกมของ Yuzusoft บทสนทนาไม่ได้ถูกเก็บเป็นไฟล์ข้อความ `.ks` ธรรมดา แต่จะถูกคอมไพล์เป็นไบนารีฟอร์แมตนามสกุล `.ks.scn` ซึ่งมีโครงสร้างเป็น **PSB (M2 / FreeMote)**:
* Magic Header: `b'PSB\x00'` (4 ไบต์)
* ข้อมูลภายในจัดเก็บในรูปแบบ Hierarchical Tree (คล้าย JSON Binary) ประกอบด้วย Trees, Objects, Arrays, Numbers, และ Strings

---

## 2. การเข้ารหัสไฟล์สเกนาริโอ (Dual-Key XOR Stream Cipher)

ไฟล์ `.ks.scn` ภายใน Archive (`scn.xp3` หรือ `patch_extra.xp3`) มักถูกเข้ารหัสด้วย **Dual-Key XOR Cipher** แบบแยกสองช่วง:

```text
[0 .................... 40 ............ hdr7 ............................ End]
  |-- Header (40B) -----|
  |--- ช่วงที่ 1: XOR ด้วย 0x01 ----------|--- ช่วงที่ 2: XOR ด้วย 0x98 ------|
```

### ขั้นตอนการถอดรหัส (Decryption):
1. **อ่าน Header 40 ไบต์แรก** แล้วทำ XOR ด้วยค่า `0x01`
2. ตรวจสอบ Magic 4 ไบต์แรกว่าเท่ากับ `b'PSB\x00'` หรือไม่
3. อ่านค่า Offset จุดตัด (`hdr7`) จากไบต์ที่ 36..39 (uint32 little-endian):
   ```python
   head = bytes([b ^ 0x01 for b in enc_data[:40]])
   assert head[:4] == b"PSB\x00"
   hdr7 = struct.unpack("<I", head[36:40])[0]
```
4. **ถอดรหัสทั้งไฟล์:**
   - ไบต์ที่ `0` ถึง `hdr7`: XOR ด้วย `0x01`
   - ไบต์ที่ `hdr7` ถึง สิ้นสุดไฟล์: XOR ด้วย `0x98`

### ขั้นตอนการเข้ารหัส (Encryption):
กระบวนการย้อนกลับเป็นกระบวนการสมมาตร (Symmetric):
- ไบต์ที่ `0` ถึง `hdr7`: XOR ด้วย `0x01`
- ไบต์ที่ `hdr7` ถึง สิ้นสุดไฟล์: XOR ด้วย `0x98`

## 3. สถาปัตยกรรมตารางข้อความ (PSB String Pool Architecture)

ในส่วนหัวของ PSB จะมี Header Table ที่ระบุตำแหน่งของตารางข้อความ:

```python
hdr = struct.unpack_from('<IIIIIIII', dec_bytes, 8)
str_off = hdr[2]  # จุดเริ่มต้นของ String Index Table
str_data = hdr[3]  # จุดเริ่มต้นของ String Payload Body
extra_off = hdr[4]  # สิ้นสุดของ String Payload Body
```

### ก. ตารางดัชนีข้อความ (String Index Table)
* `str_off + 0` (1B): Type flag
* `str_off + 1..2` (2B): จำนวนสตริงทั้งหมด (`count`)
* `str_off + 3` (1B): ความกว้างของพอยน์เตอร์ (`width_b`) ในเกม Yuzusoft ปกติจะเป็น `0x0F` (ระบุว่าพอยน์เตอร์แต่ละตัวมีขนาด 3 ไบต์ Little-Endian)
* `str_off + 4 ..`: รายการ Offset พอยน์เตอร์ ขนาด 3 ไบต์ต่อ 1 รายการ

### ข. เนื้อหาข้อความ (String Payload)
* สตริงแต่ละตัวถูกจัดเก็บแบบ Null-terminated UTF-8 (`string_bytes + b'\x00'`)
* เมื่อเราต้องการแปลบทพูด เราจะแทนที่สตริงเดิมใน String Pool ด้วยข้อความภาษาไทย
* เมื่อความยาวสตริงเปลี่ยนไป ต้องคำนวณ Offset พอยน์เตอร์ 3 ไบต์ใหม่ทั้งหมดสำหรับทุกสตริงที่อยู่ถัดไป

## 4. ข้อควรระวังขั้นวิกฤต: ป้องกัน Syntax Error (`start.ks:43`)

ในการแปลบทสนทนา มีข้อห้ามทางเทคนิคที่ต้องปฏิบัติตามอย่างเคร่งครัด มิเช่นนั้นเอนจิน KAG ของ Kirikiri Z จะเกิดข้อผิดพลาดร้ายแรง:

> **ตัวอย่างข้อผิดพลาดที่เคยเกิดขึ้น:**
> ```text
> 致命的なエラーが発生しました。
> ファイル:start.ks 行:43
> タグ:不明(←エラーの発生した前後のタグを示している場合もあります)
> Syntax error (syntax error)
> ```

### 1. ห้ามมี Literal Newline (`\n`) ในข้อความบทพูด
* **สาเหตุ:** เอนจิน KAG3 อาศัยสัญลักษณ์ขึ้นบรรทัดใหม่ในการตัดคำสั่งแท็กสคริปต์ หากในข้อความสตริงมีตัวอักขระขึ้นบรรทัดใหม่ `\n` (ASCII `0x0A`) ฝังอยู่ ตัวแยกวิเคราะห์ (Parser) จะเข้าใจผิดว่าคำสั่งนั้นยังปิดแท็กไม่สมบูรณ์ และโยนข้อผิดพลาด **Syntax error** ที่ `start.ks:43`
* **วิธีแก้:**
  - ลบตัวอักษร `\n` และ `\r` ทั้งหมดออกจากข้อความแปล
  - หากต้องการตัดบรรทัด ให้ใช้การแบ่งวรรค หรือใช้แท็กขึ้นบรรทัดใหม่ของเอนจินเฉพาะเท่านั้น

### 2. หลีกเลี่ยง Single Quote (`'`) แบบ ASCII
* **สาเหตุ:** ในบทพูดที่มีเครื่องหมาย Single Quote เช่น `don't`, `it's` ตัว Parser ในบางสคริปต์จะมองว่าเป็นการเปิดสตริงในคำสั่ง TJS
* **วิธีแก้:** แปลงเครื่องหมาย Single Quote เป็น Double Quote หรือลบออก/ใช้ภาษาไทยที่ไม่จำเป็นต้องมี Single Quote

### 3. รักษารูปแบบชื่อตัวละคร (Speaker Names)
* ใน PSB ชื่อตัวละครอาจถูกอ้างอิงผ่านตาราง Name Table แยกต่างหาก
* ห้ามสลับหรือแก้ไขลำดับใน Name Table หากไม่จำเป็น ให้แก้เฉพาะในส่วนบทสนทนา (Dialogue Strings)
